   35: =head1 DESCRIPTION
   36: 
   37: This module parses GEDCOM genealogy files and creates an interactive map showing
   38: the locations of births, marriages, and deaths. Events at the same location are
   39: grouped together in a single marker with a scrollable popup.
   40: 
   41: =head1 SUBROUTINES/METHODS
   42: 
   43: =head2 onload_render
   44: 
   45: Render the map.
   46: It takes two mandatory and one optional parameter.
   47: It returns an array of two elements, the items for the C<head> and C<body>.
   48: 
   49: =over 4
   50: 
   51: =item B<gedcom>
   52: 
   53: L<GEDCOM> object to process.
   54: 
   55: =item B<geocoder>
   56: 
   57: Geocoder to use.
   58: Its results are read through the coordinates in C<lat> and C<long>/C<lng> -
   59: through C<latitude()>/C<longitude()> when the geocoder returns an object -
   60: so L<Geo::Location::Point> and anything else L<HTML::OSM> accepts will do.
   61: A result's C<database> says which local dataset answered, and an
   62: L<Geo::Coder::Free> result therefore does not attract the courtesy delay that
   63: a remote service gets.
   64: 
   65: =item B<google_key>
   66: 
   67: Key to Google's map API.
   68: 
   69: =item B<debug>
   70: 
   71: Enable print statements of what's going on
   72: 
   73: =back
   74: 
   75: =head1 FEATURES
   76: 
   77: =over 4
   78: 
   79: =item * Extracts births, marriages, and deaths with location data
   80: 
   81: =item * Geocodes locations using multiple fallback providers
   82: 
   83: =item * Groups events at the same location (within ~0.1m precision)
   84: 
   85: =item * Color-coded event indicators (green=birth, blue=marriage, red=death)
   86: 
   87: =item * Sorts events chronologically within each category
   88: 
   89: =item * Scrollable popups for locations with more than 5 events
   90: 
   91: =item * Persistent caching of geocoding results
   92: 
   93: =item * For OpenStreetMap: centers on location with most events
   94: 
   95: =back
